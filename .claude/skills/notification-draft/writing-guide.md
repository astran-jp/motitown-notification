# お知らせ原稿の書き方(形式と規則)

## 出力形式

Markdown 1ファイル。先頭に YAML frontmatter、続けて本文。HTML は書かない。
このファイルが後工程(HTML作成 → SQL作成)の唯一の文言ソースになる。

```markdown
---
number: 21                      # お知らせ番号(ディレクトリ名)
title: モチタン・モチスピにコースを追加しました   # 一行。<title> と h1 に使う
date: 2026/9/10 15:00           # 配信日時。ブリーフに無ければ "TBD"
apps: [motitan, motispi]        # 配信対象アプリ。motitan / motispi の一方または両方
author: 神谷創
banner: 新コース追加            # ヘッダーバナーに載せる短い文言。1行8文字以内が目安(長いと文字が縮む)。2行にするなら「／」で区切る
---

# タイトル(frontmatter の title と同じ)

モチタン・モチスピを開発している神谷です。

リード文(何が変わったか。1〜3文)。

## 見出し(トピックが複数あるときだけ)

本文。

操作手順は次の形で1行ずつ:
マイページ > 設定 > 学習設定 > ○○

- 箇条書きは項目の列挙に使う

※注記(商標表記など。ブリーフにある文はそのまま転記)

開発者 神谷創
```

## 文体

- 書き手は persona.md の神谷創。「です・ます」調、一人称「私」/「私たち」
- 冒頭は「モチタン・モチスピを開発している神谷です。」で始める。末尾は署名「開発者 神谷創」で終える
- 結論(何が変わったか)を先に、理由・こだわりは後に、それぞれ短く
- 過去のお知らせ(モチベア口調「〜だよ！」「〜してね！」)は文体の参考にしない。構成(タイトル→日時→リード→トピック→注記)だけ踏襲する
- 絵文字、顔文字、「！」の連打は使わない。「！」は多くて一つ

## 内容

- 事実はブリーフに書かれたものだけ。日付・数値・仕様・機能名を推測で足さない。不明な項目は `TBD` と書いて残す
- 機能の性質・効果・使い心地(例:「自然な会話をつなげてくれます」「しっかり受け止めます」)も、ブリーフに書かれていなければ書かない。書けるのは「何が追加/変更されたか」と「どう操作するか」まで
- 「私たちはこういう体験を届けたい」というこだわりの一文は、本文全体で **1文まで**。リード文の直後ではなく、本題(変更内容と操作手順)の後に置く
- 読者への励まし・呼びかけ(「まずは気軽に〜してみてください」「〜していただけるはずです」)は書かない
- **質問・募集の禁止**: 読者への問いかけ(「〜ましたか。」「〜ですか？」)、感想・意見・要望の募集(「教えてください」「お聞かせください」「フィードバック」)は一切書かない。お知らせは一方向の告知で、返信の対応業務を増やさない
- **用語はアプリの表記に忠実に**: 機能名・画面名・ボタン名・タブ名は `glossary.txt`(公式UI用語集)の表記だけを使う。用語集に無い呼び名を作らない。名詞をつなげた造語(「フレーズ対戦機能」「単語スキップ機能」)も禁止。機能を説明したいときは用語集の語と普通の日本語で「フレーズ帳から対戦をプレイできるようになりました」のように書く
- 内部名(Book、WordBook、DetailAutoplay 等の開発用語)は UI に出ないので使わない。Notion のタスクや開発資料の言葉をそのまま持ち込まない
- 操作手順の区切りは半角 `>` と半角スペース(`A > B > C`)
- 商標注記(英検®、TOEIC®、IELTS 等)はブリーフや過去原稿の文言を一字一句そのまま
- 長さの目安: リード 1〜2文、トピックごと 2〜4文。全体で 200〜450字(注記を除く)。ブリーフが短ければ原稿も短くする

## 禁止

- **禁句**: `banned-words.txt` の語(会社名など)。`banned-patterns.txt` の表現(質問・募集・モチベア口調)。どちらも lint で機械的に弾かれる
- 「住人のみなさん」「モチベアです」など、作品世界の住人としての名乗り
- 未確認の対応予定・復旧時刻の断言(ブリーフに無ければ書かない)
- HTMLタグ、インラインスタイル
